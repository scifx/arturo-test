# vector-math 反馈

## 已验证

- 本地模块应使用 `import ./{vector}!`。省略 `!` 时，库里的函数不会进入当前作用域。
- `if standalone?` 可以区分“作为主脚本跑单元测试”和“被导入只提供函数”。
- 用户函数的 `;; description` 能被 `info.get 'vecAdd` 读到，和 builtin 的查字典路径一致。
- 2D 模长用 `hypot`，n-D 用 `sqrt` + 点积，结果与 3-4-5、5-12-13 整数三角形一致。
- `write.json report null` 再 `read.json` 后，整数 block 仍是 `:integer`，适合断言。

## 可反馈给 skill 的点

- 建议增加一个“数值矢量” recipe：展示 `couple` + `map`/`fold`、`//` 与 `/` 的区别、以及 `@[neg 1 2]` 写法。
- 官方 `couple` 示例注释写成 `[[1 "one"] ...]`，当前 runtime 实际是 `[["one" 1] ...]`。应以 runtime 为准，并修正文档。
- `[-1 2]` 在当前 parser 里是 `[ - 1 2 ]`（symbol + 两个整数），不是含 `-1` 的矢量。这个坑应该写进 skill 的 collections/numbers 经验。
- `module` + `method.public` 搭配参数类型标注 `:block` 时，在嵌套 `map` 里会触发 `is? :block a` 断言失败；无类型标注则可运行。skill 若介绍 `module`，应注明这一差异，或推荐本项目这种 `function` + `import` 组织方式。
- 中缀 `and?` / `or?` 很容易因为右到左求值吃错参数。项目里一律写成前缀 `and? (3 = size a) (3 = size b)`。
