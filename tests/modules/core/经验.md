# Core 经验

1. 写 Arturo 前先查字典：`info 'name` 或 `info.get 'name`。
2. 需要把变量名传给函数时使用 literal：`'x`；读取用 `var 'x`，写入用 `let 'x value`。
3. 块 `[...]` 默认是数据；只有 `do block` 或函数按 action 参数消费时才执行。
4. 属性不是 kwargs，而是属性栈；用户函数要消费属性，至少保留一个参数占位，调用时传 `null`。
5. 默认参数推荐模板：

```arturo
default: function.inline [name value][
    let name ((attr name) ?? value)
]
```

## 模块化（来自 `tests/projects/vector-math` 实测）

`\name` 是 `this\name` 的简写。**声明字段和调用兄弟时写成 `this\name`。**

```arturo
; 模块内的函数：this\bang
box: module [
    bang: function [s :string][ ~"|s|!" ]
    greet: method.public [name :string][
        this\bang ~"hi |name|"
    ]
]
export box!
```

模块体顶层没有 `this`，不能写 `this\bang: function [...]`。字段声明仍用 `bang: function [...]`；`init` / method 里赋值才写 `this\ops: ...`。

### 外部函数 + 模块 ≈ Python `__init__.py`

外面写函数，模块当包入口去 import：

```arturo
; ops.art — 子模块，函数要自包含（lean 后看不见兄弟名）
pairAdd: function [pair][ (get pair 0) + get pair 1 ]

; vector.art — __init__.py
vector: module.with: [] [
    init: method [][
        this\ops: import.lean ./{ops}!
    ]

    vecAdd: method.public [left :block right :block][
        map couple left right 'p [
            this\ops\pairAdd p
        ]
    ]
]
export vector!
```

`import.lean` 返回 dictionary，不污染文件全局：`set? 'pairAdd` 和 `set? 'ops` 都是 false。

### 作用域上踩过的坑

1. **method 里直接 `import ./{ops}!`** 可以，但导入函数的 arity 常丢失。`unless numericValue? k [throw]` 会变成 `unless <fn> 2`。`out: bang msg` 可能只绑到函数本身。要嘛括号写成 `(numericValue? k)`，要嘛走 `this\ops\name`。
2. **`import.lean` 会隔离被导入文件。** 文件里 `ensurePair` 不能再裸调 `numericValue?`。helper 必须自包含，或不要用 lean。
3. **文件顶层 `import ./{ops}!`** 会泄漏 `pairAdd` 到全局，不像 `__init__.py`。
4. **公开方法不要叫 `add` / `sub` / `div`。** `export` 后会盖住算术 builtin，`+` 会递归进自己的 method。
5. **`standalone?` 在 `import` 进来的文件里是 false**（像 `__name__ == "__main__"`）。但只对 `import` 成立。
6. **`export.all` 会把私有方法也导出。** 默认 `export` 只出 `.public`。
