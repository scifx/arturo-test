# Core 经验

1. 写 Arturo 前先查字典：`info 'name` 或 `info.get 'name`。
2. 需要把变量名传给函数时使用 literal：`'x`；读取用 `var 'x`，写入用 `let 'x value`。
3. 块 `[...]` 默认是数据；只有 `do block` 或函数按 action 参数消费时才执行。
4. 属性不是 kwargs，而是属性栈；用户函数要消费属性，至少保留一个参数占位，调用时传 `null`。
5. 默认参数推荐模板：

```arturo
default: function.inline [name value][
    let name ((attr name) ?? value)
]
```

## 模块化（来自 `tests/projects/vector-math` 实测）

对照官方 [`module`](https://arturo-lang.io/documentation/library/core/module/) / [`export`](https://arturo-lang.io/documentation/library/core/export/) 和 `agent-shell.art` 的文件拆分，当前 runtime 上可落地的写法是：

```arturo
vector: module [
    pairAdd: function [pair][
        (get pair 0) + get pair 1
    ]

    vecAdd: method.public [left :block right :block][
        map couple left right 'p [
            \pairAdd p
        ]
    ]
]

export vector!
```

规则：

1. **模块里可以放 `function`，但对外入口必须是 `method.public`。** `export` 只导出公开方法；内部 `function` 留在模块里，`set? 'pairAdd` 为 false。
2. **兄弟调用一律 `\name`。** 方法调函数、函数调函数、方法调方法都一样。写成裸 `pairAdd` 会在 `export` 时报 `Identifier not found`。官方示例里的 `\namedRule` / `|\namedRule title width|` 就是这个。
3. **公开方法不要叫 `add` / `sub` / `div`。** `export` 之后会盖住算术 builtin。名为 `add` 时，方法体里的 `(get p 0) + get p 1` 会递归进自己，表现为 `is? :block left` 或 `couple` 吃到整数。安全名：`vecAdd`、`greet`、`section`。
4. **两层模块化不要混为一谈。**
   - 语言模块：`module` + `method.public` + `export`
   - 文件模块：`import ./{vector}!` + `if standalone?`（`agent-shell.art` 的主路径）
   - 实战里两者叠用：文件里定义并 `export` 语言模块，调用方 `import` 该文件。
5. **`export.all` 会把私有方法也导出。** 默认 `export` 只出 `.public`。`type vector` 仍是 `:module`，`set? 'vector` 仍为 true。
6. **`module.with: [args]` 配 `init:`** 适合带初始状态的模块（官方第二个示例）。无状态工具库不必用。
7. **`method` 的 `;; description` 目前挂不上。** `info.get` 看到空描述、参数变成 `:any`。需要文档时把逻辑放内部 `function`，或另写 Markdown。
8. **不要用 `vector\vecAdd` 当常规调用。** 未 `export` 时路径调用不稳定；`export` 之后直接 `vecAdd [1 2] [3 4]`。
