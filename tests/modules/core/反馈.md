# Core 反馈

## 已验证

- `info.get 'map` 在 bundled runtime 中返回 `:dictionary`，包含 `name/module/example` 等字段。
- `info.get` 的 `example` 字段可作为官方示例入口，适合后续自动抽样验证。
- `'value` 是 `:literal`，可通过 `var` 解引用，通过 `let`、`inc` 等写回原绑定。
- 默认参数 helper 依赖 `function.inline`，否则 `let` 会写入 helper 自己的作用域。
- 官方 `module` + `method.public` + `export` 可运行；内部可放 `function`，兄弟调用用 `\name`。见 `module-export.art` 与 `tests/projects/vector-math`。
- `export` 后 `set? 'publicMethod` 为 true，内部 `function` 不会进当前作用域。

## 可反馈给 skill 的点

- 默认参数模式对新手不直观：必须说明“函数至少一个 placeholder 参数才能消费属性”。
- `info.get` 示例可以作为 skill 的测试种子来源，后续可增加自动提取官方 examples 的 runner。
- `module` 文档应写明：内部 `function` + 对外 `method.public` + `\name` 互调。只写 `method` 容易让人以为模块里不能放函数。
- 公开方法禁止使用 `add`/`sub`/`div` 这类算术名；否则 `+` 会绑到自己的 method。
- `method` 的 `;;` 数据注释目前不能像 `function` 那样被 `info.get` 读到。
