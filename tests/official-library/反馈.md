## 暂不原样整模块执行的模块与原因

这些模块的示例仍然已导入 `官方示例.md`，只是不能未经改写就放进自动回归：

| 模块 | 原因 |
|---|---|
| `collections` | 原始示例中存在当前 runtime 不兼容/疑似陈旧写法，例如 `contains? dict "John"` 报错。|
| `core` | 包含 `call.external` / 外部动态库示例，缺少 `libmylib.so`。|
| `databases` | 示例依赖数据库状态，原样跑会出现表不存在等问题。|
| `exceptions` | 包含当前 runtime 未解析的错误类型名/示例差异。|
| `files` | 包含远程 URL 读取等网络相关示例。|
| `io` | 包含 `input`，非交互测试会 EOF。|
| `iterators` | 原样整模块执行会超时/长时间输出，需要拆分或跳过无限/惰性示例。|
| `logic` | 有原始示例片段解析失败，需要逐条改写。|
| `net` | 网络相关，环境依赖强。|
| `numbers` | 存在当前 runtime 未解析函数，例如 `angle`。|
| `reflection` | 可执行但输出极大，暂不放入默认回归，避免噪音。|
| `sockets` | 启动 socket server，原样执行会等待/超时。|
| `strings` | 存在当前 runtime 未解析/疑似陈旧函数，例如 `upper?`。|
| `system` | 包含环境/编码/进程相关差异，原样执行不稳定。|
| `types` | 有示例片段解析失败，需要逐条清理。|
| `ui` | UI 功能在当前 MINI/无 UI 环境不可用。|

## 给 skill 上游的建议

- 确认 `window` 是否应保留在 library index；如果是 UI-only/build-gated symbol，建议在 index 中标注 runtime/build 条件。
- 将 `info.get` 官方示例按“纯计算 / 文件 / 网络 / UI / 交互 / 长耗时 / 需外部资源”分类，便于自动执行更大范围的官方示例。
- 对陈旧示例建立回归清单：`collections contains?`、`numbers angle`、`strings upper?` 等可优先核对。
