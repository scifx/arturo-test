# 2026-08-19 对话总结

本文件记录今天与用户讨论后形成的关键决策，便于后续 agent 接手时理解项目为什么这样组织。

## 1. 起点：安装 skill 并创建 Arturo 示例仓库

用户最初要求：

- 安装 `scifx/arturo-language-skill`。
- 写一些测试。
- 创建项目主干和 README。
- 该仓库用于辅助 skill 创建，并为 agent 写 Arturo 代码提供大量可验证、实用的示例。

初始实现曾把 skill 复制到仓库中，但随后被纠正。

## 2. 重要纠正：不要提交上游 skill

用户指出：

> 上游 skill 会经常更新，需要每次测试时获取，不应该包含到此代码仓库提交之下。

随后又进一步明确：

> 不要有自动获取脚本呀，skill 在项目 README 里提到自己拉取就好了，每次跑一个 fetch 一次，太慢，也太费时间和资源。

最终形成的约定：

- 不 vendor skill。
- 不提交 skill runtime。
- 不在普通测试中自动 fetch/clone。
- README 只说明如何手动准备 skill。
- `run-all.sh` 只使用已有 runtime。

## 3. 测试文件夹必须有说明、反馈、经验

用户要求每个测试文件夹都要有：

```text
README.md
反馈.md
经验.md
```

目的：

- 方便上游 skill 收集反馈。
- 方便积累可验证 Arturo 代码。
- 方便沉淀 agent 写 Arturo 的经验。

因此当前 `tests/modules/`、`tests/official-library/`、`tests/projects/` 都遵循该结构。

## 4. 参照 Arturo 官方 library 模块分区

用户要求：

> 文件夹要记得分区放好，最好可以参照 arturo 语言的模块分区开始，验证官方例子开始。

因此补齐了 26 个官方模块目录，并将官方 `info.get` 示例导入每个模块的 `官方示例.md`。

## 5. 从官方示例验证做起

用户进一步要求：

> 先把 library 里的示例弄上去，作为默认的示例。

并提醒：

> 可以用 python 结合 arturo 的 `info.get 'x | get 'example` 这样批量把示例填充到各个文件夹，当然你先试一下小范围，可以就大范围应用，然后批量跑通他们。

实际执行路线：

1. 先小范围试 `arithmetic`。
2. 确认 raw official examples 可以整模块运行。
3. 批量导出所有 521 个 symbol 的 904 段官方示例。
4. 探测哪些模块可以整模块原样跑通。
5. 只把稳定可跑的模块加入默认回归。
6. 其余模块保留在 `官方示例.md`，后续逐条 curated 改写。

## 6. 增加实战项目文件夹

用户提出还可以有实战项目文件夹。

因此新增：

```text
tests/projects/
```

首个项目是：

```text
tests/projects/word-frequency/
```

用于验证文本处理、dictionary 统计和 JSON 输出的组合。

随后用户要求再写一个矢量计算模块，作为项目测试并遵守本仓库规则。因此新增：

```text
tests/projects/vector-math/
```

实现可导入的 `vector.art`（加减、缩放、点积、叉积、模长、单位矢量、距离）和 `vector-math.art` 场景测试，并按约定补齐 `README.md`、`反馈.md`、`经验.md`。

随后用户纠正：矢量项目留在 `tests/projects/`，模块小测试放官方 `tests/modules/core/`，项目里的模块经验要浓缩进官方对应目录方便查阅。并提示模块里可以放 `function`，对外调用必须走 `method`。因此：

- `vector.art` 改为官方 `module`：内部 `function` + `method.public` + `export`。
- 新增 `tests/modules/core/module-export.art`。
- 模块化规则写入 `tests/modules/core/经验.md`。

用户继续纠正：`\name` 是 `this\name` 的简写，声明最好写 `this\name`；并指出模块有作用域，函数可以写在外面再 import 进 function/method，类似 Python `__init__.py`。因此矢量包拆成 `ops.art` + `vector.art`（`init` 里 `this\ops: import.lean`），官方分区补上 `module-scope-import.art`。

## 8. 当前项目方案的核心原则

1. 官方示例先入库，作为默认素材。
2. 可原样运行的官方示例进入 `official-examples-smoke.art`。
3. 不能原样运行的官方示例不丢弃，保留在 `官方示例.md`，再逐步 curated 改写。
4. 每个模块都同时记录说明、反馈、经验。
5. 实战项目用于验证多模块组合写法。
6. skill 手动准备，测试不自动联网。
7. 每次重要工作写入 `docs/YYYY-MM-DD/`。
