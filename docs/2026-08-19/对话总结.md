## 2. 重要纠正：不要提交上游 skill

用户指出：

## 10. 模块里可以放 function，对外必须走 method

> 我给你个小提示，其实模块里面可以放 function 的，只是最终得把调用放到 method 里。

## 11. `\name` 是 `this\name`，声明写清楚

> `\name` 是 `this\name` 的简写，看情况，声明最好用 `this\name` 会更清晰。你的矢量项目已经包装为模块了吗？

是的，当时已经是 `module`。之后调用和字段赋值改成显式 `this\name`。

## 12. 模块有作用域：外面写函数，再 import 进内部

> 另外模块还有作用域问题，你完全可以在外面写函数，然后试着 import 到 function 和 method 函数内部试试，这样就类似 python 的 `__init__.py` 了。

实测后稳定写法：`ops.art` 放 helper；`vector.art` 的 `init` 里 `this\ops: import.lean ./{ops}!`。method 里直接 `import` 会丢 arity。

## 14. 当前项目方案的核心原则

1. 官方示例先入库，作为默认素材。
2. 可原样运行的官方示例进入 `official-examples-smoke.art`。
3. 不能原样运行的官方示例不丢弃，保留在 `官方示例.md`，再逐步 curated 改写。
4. 每个模块都同时记录说明、反馈、经验。
5. 实战项目用于验证多模块组合写法。
6. skill 手动准备，测试不自动联网。
7. 每次重要工作写入 `docs/YYYY-MM-DD/`。
8. **用户当次提醒写入当天 `对话总结.md`。**
9. 模块小测试在 `tests/modules/<对应官方模块>/`，实战项目在 `tests/projects/`，项目经验浓缩回官方分区。
10. 抽 skill 前要读网页总章，不能只靠 `info.get`。
